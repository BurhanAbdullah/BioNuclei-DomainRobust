When the microscope changes, does the AI still work?

BioNuclei-DomainRobust is a research programme for reliable nuclear instance segmentation across heterogeneous fluorescence bioimaging. We study the gap between excellent performance on a controlled benchmark and dependable behavior when images come from a different biological or imaging domain.

Bioimaging is the starting point

Modern biological imaging turns invisible cellular structure into measurable data. Fluorescence microscopy can reveal nuclei, proteins, organelles and tissue organization, but the resulting images are shaped by optics, dyes, acquisition settings, sample preparation and biological context. Bioimage analysis therefore has to cope with variation that is scientific—not merely cosmetic.

What the computer sees. Fluorescence microscopy can make nuclei highly visible, but intensity, morphology, density and background vary across experiments. Image: DAPI-stained HaCaT keratinocytes, Wikimedia Commons, CC BY-SA.
Where the data come from. Real bioimaging workflows combine samples, fluorescent labels, optics, detectors and acquisition software. Image: Nikon inverted fluorescence microscope, Wikimedia Commons, CC BY.
The problem we target: the same biological object can look different when the imaging domain changes. A robust segmentation system should learn the biological task without becoming overly dependent on one narrow image distribution.

What we actually do

We build an auditable experimental chain from source-domain training to unseen-domain evaluation. The target domain is kept out of source training, and scientific claims are promoted only when the corresponding evidence artifact passes predefined checks.

The current AI stack

Core scientific model

Boundary U-Net

The current E4 implementation trains a Boundary U-Net for nuclear instance segmentation. The model operates on images and segmentation targets; it is not an LLM and does not require a language model to produce the segmentation masks.

Implementation evidence: scripts/train_domain_robust.py instantiates BoundaryUNet and applies source-domain training with the configured domain-robust pipeline.

LLM layer — important distinction

No LLM is part of E4 segmentation

The current scientific segmentation result should not be described as being generated by GPT, Claude or another LLM. No LLM is required for the core E4 model. This separation keeps the biological measurement pipeline reproducible and avoids conflating language-model assistance with the trained vision model.

LLMs can, however, become useful at the orchestration and reasoning layer of the future Bio-MCP: selecting tools, inspecting provenance, planning experiments, comparing artifacts and explaining results.

What we mean by a Bio-MCP

The Bio-MCP is a proposed agent-accessible interface around the bioimage research workflow. The idea is analogous to a structured tool layer for engineering systems: an LLM should not directly invent scientific operations; it should call explicit, typed tools whose inputs, outputs and provenance can be audited.

1 · Dataset tools

Resolve dataset manifests, verify checksums, inspect image dimensions, identify biological units and enforce source/target separation.

2 · Bioimage tools

Run controlled preprocessing, intensity normalization or perturbation, image-quality checks and segmentation workflows.

3 · Experiment tools

Launch pre-specified training, evaluation, ablation and transfer experiments with fixed configurations and seeds.

4 · Scientific metric tools

Compute Dice, IoU, precision, recall, F1, AJI and boundary-F1, with image-level records retained.

5 · Failure-analysis tools

Group failures by observable image characteristics and expose where domain shift is degrading performance.

6 · Provenance tools

Return the exact dataset version, configuration, code commit, seed, workflow run and artifact associated with a result.

Key design rule: the LLM would be the reasoning/orchestration layer; the Bio-MCP tools would perform the actual scientific operations; the repository artifacts would remain the source of truth. The MCP concept is a proposed research direction here, not a completed validated contribution yet.

Those claims require the remaining comparative experiments.

Why seven metrics?

Dice + IoU

Measure overlap between predicted and reference nuclear regions.

Precision + recall + F1

Expose false detections and missed nuclei that a single overlap score can hide.

AJI

Provides an instance-aware view of segmentation quality across nuclei.

Boundary F1

Tests contour fidelity and separation quality, especially important for touching or irregular nuclei.

Research direction

Bio-MCP

Formalize typed bioimage tools, provenance contracts and LLM orchestration only after the underlying scientific workflow is stable enough to expose as reliable tools.

Reproducibility by construction

✓ Leakage control

Target-domain images are excluded from source training in the E4 protocol.

✓ Complete target gate

E4 requires 79 target images and 79 per-image records before promotion.

✓ Versioned artifacts

Results are tied to workflow runs, code commits, configuration and provenance.

✓ Failure transparency

Failed experiments and engineering blockers are retained rather than silently removed.
