BioMCP is the interoperability product. It discovers and launches validated scientific servers, generates client configuration, and keeps tool invocation separate from the scientific software that performs the measurements.

PowerMCP-style workflow

Install once. Discover. Configure. Run.

This is the product pattern we are adopting from the useful parts of PowerMCP: a small installer/CLI around canonical servers rather than a pile of duplicated scripts.

01 · InstallInstall the backend MCP extra and BioMCP CLI.
02 · ListSee the available BioMCP server packs.
03 · DoctorCheck MCP SDK, server command and checkpoint readiness.
04 · ConfigureGenerate or update an MCP client configuration.
05 · RunLaunch a server over stdio or use hosted HTTP.
Quick start

The five commands users need.

python -m pip install -e '.[mcp]'
biomcp --version
biomcp list
biomcp doctor
biomcp install
biomcp run bionuclei

The installer updates only the mcpServers entry it owns and preserves unrelated client configuration. Use biomcp install --dry-run before writing anything.

Architecture

BioMCP connects. The scientific product measures.

BioMCP does not reimplement BioNuclei. It calls the validated scientific backend and returns structured outputs so an agent can reason over actual artifacts.

BioMCP owns

Interoperability

Installer, server discovery, client configuration, transports, schemas, tool naming, safety boundaries, versioning and compatibility.

BioNuclei owns

Scientific measurement

Segmentation, post-processing, metrics, experiments, benchmark protocols, scientific artifacts and claims.

Testing

Every layer gets tested independently.

The BioMCP CI lane checks CLI version/listing, dry-run behavior, configuration generation and package integration. MCP server testing remains separate from scientific benchmark validation.
