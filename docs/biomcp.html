BioMCP is the interoperability layer between AI and scientific software.

BioMCP is a separate, open-source platform for biology, bioinformatics, bioimaging and scientific AI. Its purpose is not to replace scientific software, but to make real scientific capabilities discoverable, callable, configurable and auditable from modern AI hosts and agents through the Model Context Protocol.

Platform architecture

One scientific interoperability layer. Many capabilities.

BioMCP is being developed as a PowerMCP-class scientific platform: a unified registry, CLI, configuration layer and MCP runtime that can connect AI hosts to carefully validated scientific software and model providers.

BioMCP platform vision. The diagram represents the long-term architecture; individual integrations are introduced only after implementation and validation.

AI orchestrates. Scientific software measures.

BioMCP separates language-model reasoning and workflow orchestration from scientific computation. The model may plan and select an operation, but the underlying scientific software remains responsible for the measurement, computation, artifact or validated domain result.

How it works

From a research question to structured scientific evidence.

01 · Researcher

Defines the scientific question, analysis or workflow.

02 · AI host / agent

Plans the task, discovers capabilities and selects permitted tools.

03 · BioMCP

Resolves registry metadata, validates a typed MCP call and routes it to the selected capability.

04 · Scientific software / model

Performs the actual computation, measurement or model inference under the integration's controls.

05 · Result + evidence

Returns structured output, provenance and execution evidence where supported.

Core platform

BioMCP is more than an MCP wrapper.

Registry & discovery

A machine-readable registry describes integration lifecycle, installation metadata, transport and capabilities. Planned software is not presented as installable.

Unified CLI & configuration

The platform is built around operational workflows such as install, list, run, doctor and client configuration, with diagnostics and dry-run support.

Real MCP interoperability

Validation should exercise actual MCP client/server paths, installed artifacts and external dependencies rather than relying only on source imports or documentation claims.

LLM Gateway

A first-class scientific AI subsystem.

The LLM component is being expanded from its initial OpenAI-compatible bridge into a provider-agnostic gateway for scientific AI orchestration.

Model providers

Target provider abstraction for OpenAI-compatible endpoints, local/self-hosted runtimes such as Ollama and vLLM, and compatible custom endpoints.

Agent capabilities

Target model discovery, streaming, structured outputs, JSON/schema responses, tool/function calling, context/session controls and provider capability metadata.

Scientific orchestration

Target controlled MCP tool discovery and execution so an LLM can coordinate scientific software while preserving typed inputs, bounded resources, provenance and scientific responsibility.

The gateway expansion is a development target, not a claim that all of these capabilities are already implemented or validated.

Scientific boundary

AI orchestrates. Scientific software measures.

BioNuclei remains the scientific source of truth for its own models, measurements, evaluation, artifacts and provenance. BioMCP provides interoperability around scientific systems; it does not copy or reimplement the BioNuclei scientific engine.

Use BioMCP

Start locally, then connect an AI host.

pip install biomcp
biomcp list
biomcp doctor

# Run a current server
biomcp run bioimage

# Generate generic MCP configuration
biomcp install --servers bioimage --clients generic

# Preview without writing configuration
biomcp install --servers bioimage --clients generic --dry-run

The complete installation and client configuration documentation lives in the BioMCP repository. ImageJ/Fiji requires an explicitly configured local executable. The current LLM bridge uses environment-provided endpoint and credential configuration.
