BioMCP — Scientific Software Interoperability Framework

BioMCP is an open-source framework for integrating scientific software, computational tools, model runtimes and data resources through standardized Model Context Protocol (MCP) interfaces.

Open BioMCP on GitHub →Join the community →
System architecture

A common interface for heterogeneous scientific software.

BioMCP is being developed as a software-integration platform comprising a capability registry, command-line interface, configuration layer and MCP runtime. Scientific applications remain the computational backends; BioMCP provides the interface and execution boundary around them.

System architecture and long-term integration model. Individual components are introduced only after implementation and validation.

Separation of interface and computation

BioMCP handles discovery, routing, configuration, protocol interfaces and execution controls. Scientific software remains responsible for domain-specific computation, measurement, model inference and scientific artifacts.

Execution model

From MCP request to scientific computation.

01 · Client

An MCP-compatible client issues a typed request against a registered capability.

02 · Registry

BioMCP resolves the integration metadata, transport and declared capability.

03 · Runtime

The runtime validates the request and applies configuration and execution controls.

04 · Scientific backend

The selected application, executable, model runtime or external MCP server performs the operation.

05 · Structured result

The integration returns typed output and, where available, execution metadata and provenance.

Platform components

Infrastructure for reproducible scientific software integration.

Capability registry

A machine-readable registry describes integration lifecycle, installation metadata, transport and exposed tools. Registry status distinguishes planned, experimental and validated components.

CLI & configuration

A unified command-line interface provides operational workflows including install, list, run, doctor and client configuration, with diagnostics and dry-run support.

MCP runtime

Integration testing exercises actual MCP client/server communication, packaged artifacts and external runtime dependencies rather than relying only on source-level imports.

Model-runtime integration

LLM Gateway

BioMCP includes an experimental model-runtime integration layer. Its purpose is to provide a common control and interface boundary for language-model endpoints used in scientific workflows.

Provider abstraction

Target interfaces include OpenAI-compatible endpoints, local runtimes such as Ollama and vLLM, and compatible custom endpoints.

Model interface

Planned capabilities include model discovery, request/response handling, streaming, structured outputs, JSON schema and tool/function calling.

MCP integration

Planned controls include MCP capability discovery and execution, context/session handling, provider metadata, resource limits, timeout/retry policy and provenance.

The gateway is under active development. The listed capabilities describe the target interface, not a claim that every capability is currently implemented or validated.

Scientific software boundary

Interoperability without reimplementing the scientific engine.

BioNuclei remains the scientific source of truth for its own models, measurements, evaluation procedures, artifacts and provenance. BioMCP provides interoperability around scientific systems and does not copy or reimplement the BioNuclei scientific engine.

Local installation

Command-line interface

pip install biomcp
biomcp list
biomcp doctor

# Run a current server
biomcp run bioimage

# Generate generic MCP configuration
biomcp install --servers bioimage --clients generic

# Preview without writing configuration
biomcp install --servers bioimage --clients generic --dry-run

ImageJ/Fiji requires an explicitly configured local executable. The current LLM bridge uses environment-provided endpoint and credential configuration.

Contribution lifecycle

Integration status is evidence-based.

Idea

Scientific use case and upstream project identified.

Planned

Registry entry only; not installable.

Experimental

Executable adapter and focused tests are available.

Validation

MCP, security, packaging and CI evidence are evaluated.

Validated

Documented evidence supports the integration status.
