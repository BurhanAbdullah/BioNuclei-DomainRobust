ArchitectureProposed structure

A common structure for scientific AI.

A proposed ecosystem can separate model research, interoperability, workflow composition and reusable scientific knowledge. Each layer has a defined purpose and can be developed independently.

Ecosystem structure

Four complementary layers.

This page describes the intended structure only. It is an architectural framework, not a claim that every component is implemented.

01

BioFM

Domain aware vision and multimodal foundation-model research for biological imagery.

02

BioMCP

Proposed interoperability layer for typed discovery and invocation of bioimaging capabilities.

03

BioWF

Workflow layer for versioned, reproducible and auditable scientific studies.

04

BioSkills

Knowledge layer for reusable protocols, validation rules and scientific guidance.

Capability structure

A future interface can expose explicit scientific operations.

These categories describe the intended surface of the architecture. They are targets for future development, not completed integration claims.

01

Image ingestion

Load and inspect imaging data with explicit metadata and provenance.

02

Dataset quality

Check completeness, pairing, labels and declared split rules.

03

Preprocessing

Run explicit, versioned transformations using established tools.

04

Segmentation

Invoke segmentation models and return structured outputs.

05

Quantification

Compute scientific measurements inside deterministic analysis software.

06

Evidence records

Preserve metrics, parameters, artifacts and software provenance.

Interface principle

Separate coordination from computation.

An AI agent may help interpret a research request and coordinate available operations. The scientific tools remain responsible for image analysis, measurement and other domain specific computation.

Coordination

Agent and interface layer

Discover capabilities, select operations, provide validated parameters, coordinate steps and explain recorded outputs.

Computation

Scientific software layer

Perform image analysis, measurement, visualization and validation in explicit software environments.

Status

A proposed structure, not an implementation claim.

The architecture should become more concrete through implemented components, tested interfaces and evaluated scientific workflows. Until then, the distinction between design and evidence remains explicit.
